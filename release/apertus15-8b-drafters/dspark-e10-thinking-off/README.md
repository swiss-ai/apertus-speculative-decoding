# DSpark drafter for Apertus-v1.5-8B (thinking off, epoch 10)

This is a speculative-decoding draft model (DSpark) for
[swiss-ai/Apertus-v1.5-8B](https://huggingface.co/swiss-ai/Apertus-v1.5-8B) at
revision `a411d838600baf0e3635a3daf66fb7c55fc97bb6`. It is trained for
**thinking-off** requests. It is the final checkpoint of a 10-epoch run (global
step 249,408, 2026-10-04), which is also the best validation epoch. Trained by
Yu Zhu (Swiss AI).

The Swiss AI serving platform runs this head always-on as
`SwissAI-Research/swiss-ai/Apertus-v1.5-8B-dspark-e10-k3` (k=3).

Speculative decoding does not change what the model outputs. The target model
verifies every drafted token, so with greedy decoding the output is the
target's own output. With sampling, the output distribution is the target's.
Only the speed changes.

## Intended use

- Use it to speed up serving of Apertus-v1.5-8B in vLLM when thinking is off,
  mainly for English chat, math, code and multi-turn assistant traffic at low to
  medium concurrency.
- Do not use it with other targets, other Apertus revisions or sizes, or
  thinking-on requests. Those need their own drafter. It may load, but
  acceptance, and therefore speed, is not measured there.
- It is not a standalone language model.

## Architecture

- DSpark: 5 Qwen3-style decoder layers (hidden size 4,096, 32 heads, 8 KV heads,
  MLP 21,504, sliding window 2,048). Block size 8, so it drafts at most 7 tokens
  per step.
- It has a Markov head (rank 256) and a confidence head (fed with the Markov
  embedding).
- Target features come from Apertus layers 1, 8, 15, 22 and 29.
- Draft vocabulary is 131,072 tokens. `sample_from_anchor: true` (the anchor is
  the first of the 8 slots).
- The checkpoint has no embedding table and no LM head. vLLM takes both from the
  target model at load time.
- Weights are bf16, in `model.safetensors` (3.43 GB). Optimizer state is not
  included.

## Training data and licence

The drafter was trained on the prompts of
[`mlabonne/open-perfectblend`](https://huggingface.co/datasets/mlabonne/open-perfectblend),
revision `af60f3c18201652a83a93f46fcfee1b646ba3df7` (1,420,909 rows).
**Every assistant turn was regenerated by Apertus-v1.5-8B** with thinking off
(T 0.7, top-p 0.8, top-k 20, 4,096-token cap per answer). The original answers in
the dataset were not used for training.

- Filtering: 62,128 rows were dropped (single-message UltraFeedback rows and
  empty first messages). That leaves 1,358,781 conversations and 1,809,684
  generated answers (933.7 M completion tokens).
- Rendering: conversations were rendered with the Apertus chat template (system
  prompt plus "Deliberation: disabled") and packed at 8,192 tokens.
- Split: 90/10 train/validation.

Open-PerfectBlend aggregates eight source datasets. The dataset card lists
these as Apache-2.0 or MIT. Their upstream lineage was audited before release:
[docs/release/license-audit-8b-drafters.md](TODO-link-pinned-to-commit).

## Training procedure

- Trainer: [speculators](https://github.com/vllm-project/speculators) at commit
  `7046ac63fac4eeb218dc2e92a385c7d1ec8c4e00`, plus `speculators.patch` (included).
  The patch adds support for the pruned output head and an extraction-server
  timeout.
- Objective: DeepSpec/DSpark loss, cross-entropy 0.1 + total variation 0.9 +
  confidence BCE.
- Optimizer: Muon (AdamW for non-matrix parameters), learning rate 3e-4, cosine
  schedule, 10 epochs.
- Batching: 16,384-token packing per GPU, 1,024 anchors per sequence.
- Hardware: 2 GH200 nodes (4 extraction servers and 4 trainer ranks).
- Hidden states were extracted online from the frozen bf16 target.
- Exact invocation: `train_command.txt` and `run.yaml`. Library versions:
  vLLM `0.23.1rc1.dev1029+ga601a9d99`, transformers `5.14.0.dev0`, torch
  `2.11.0+cu130`.

## How to serve with vLLM

The measurements used the Swiss AI vLLM build for Apertus 1.5, at vLLM commit
`a601a9d998ddeb488f0c17e8512874b116aa7658`. That is container
`ghcr.io/swiss-ai/vllm_apertus_1.5_release@sha256:8eb36e284fbefdd44c6f4dc23072eff9c06c1caed5643ce2f99ac7e0915a06ae`
(arm64; the Clariden SquashFS copy is `vllm_apertus_1.5_release-arm64.sqsh`,
sha256 `f5fc017ff794fa8d80b73dd9a788028a1872dbfc2e21c0de043fb7738c11a0b5`).

That build needs four source patches, all included in `serving-patches/`:

| Patch | Why |
|---|---|
| `vllm-apertus-dspark-anchor-layout.patch` | **Required.** The build translates DSpark checkpoints as if `dspark_bonus_anchor=True`, but this head was trained with `sample_from_anchor=True`. Without the patch every draft slot is off by one and acceptance collapses (a sibling checkpoint served at 1.96 instead of 4.98 accepted tokens per step). |
| `vllm-apertus-dspark-mrv2-inner.patch` | Model runner v2's DSpark loader fails on Apertus 1.5's inner language-model wrapper. |
| `vllm-apertus-eagle3-aux-layers.patch` | Auxiliary-layer helpers fail on the same wrapper. |
| `vllm-apertus-image-token.patch` | The draft proposer reads `image_token_index`, which Apertus 1.5 names `image_token_id`. |

The patches were applied as file overlays on the read-only image (see
`serving/patch-vllm.sh` in the project repository).

The deployed engine arguments:

```bash
vllm serve swiss-ai/Apertus-v1.5-8B \
  --dtype bfloat16 --tensor-parallel-size 1 --max-model-len 32768 \
  --gpu-memory-utilization 0.8 --max-num-batched-tokens 16384 --max-num-seqs 256 \
  --no-enable-prefix-caching \
  --speculative-config '{"method": "dspark", "model": "<this repo>", "num_speculative_tokens": 3}'
```

- **Thinking must be off.** Pass `chat_template_kwargs={"enable_thinking": false}`
  per request. The production deployment instead uses a chat template that
  forces thinking off.
- `num_speculative_tokens` can be 1 to 7. Use **3** for general traffic. Use
  4 or 5 for traffic that resembles the training data (math, code, English
  chat). Use 7 only for single-stream or math/code-heavy use.

## Limitations

- **Non-English text.** The training prompts are 99.55% English. On 12
  non-English languages acceptance falls to about 1.8 tokens per step. The gain
  at C=1 is only 1.1 to 1.6x (Arabic and Swahili about 1.1x). At C=128, 10 of
  the 12 languages are 8 to 33% **slower** than plain serving.
- **High concurrency.** Once the GPU is compute-bound, each rejected draft costs
  throughput.
  - At C=128 with k=3, chat (0.91x) and translation from English (0.82x) are
    slower than plain serving.
  - At k=7, chat and summarization fall below plain from about C=64.
  - Use k=3 or less under heavy load, or turn speculation off.
- **Tasks absent from training.** These include long-document summarization,
  prompts of 8k+ tokens and translation. They gain less: about 1.0 to 1.6x at
  C=1 and about plain speed at C=128.
- **Thinking on** is not covered. A separate thinking-on drafter exists.
- **Hardware and software.** Results are for GH200 with the vLLM build and
  patches above. Other GPUs, vLLM versions or batch settings will give other
  numbers.
