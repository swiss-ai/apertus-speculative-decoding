# DSpark drafter for Apertus 1.5 70B: execution plan

Goal: train a DSpark drafter for Apertus-v1.5-70B exactly as Yu trained the 8B one
(`docs/CONFIG_DSpark_Apertus_1.5_8B_09_29.md`; final checkpoint
`infra01/speculative-decoding/DSpark_Apertus_1.5_8B/dspark_apertus15-8b_open-perfectblend_thinking-off_2026-10-04_epoch10_final`),
thinking off, open-perfectblend answers regenerated by the 70B, 10 epochs.
Yu's job scripts are on branch `DSpark_Apertus_1.5_8B` (`methods/dspark/jobs/`); the
scripts here under `methods/dspark/train/` are their Clariden/70B port.

Decisions (2026-10-16): regenerate the corpus with the 70B; regeneration may use
more than two nodes; training starts on two nodes and may use more.

## Unchanged from the 8B run

| Item | Value |
|---|---|
| Prompts | `mlabonne/open-perfectblend` revision `af60f3c`, 62,128 rows without a leading user turn dropped, 1,358,781 conversations shuffled once with seed 0, four shards (`make_opb_shards.py`, same ids `opb-NNNNNNN`) |
| Regeneration | every assistant turn regenerated in order (`speculators regenerate-responses`), T 0.7 / top-p 0.8 / top-k 20, thinking off, 4,096-token answer cap, `--max-model-len 8192` |
| Prepared data | `speculators prepare-data --seq-length 8192`, trainer default 90/10 split |
| Drafter | DSpark, 5 layers, block 8, Markov rank 256, confidence head with Markov input, `sample_from_anchor`, full 131,072-row output head |
| Objective | CE 0.1 + TV 0.9 (eager), Muon lr 3e-4, cosine, 10 epochs |
| Batch | 16,384 packed tokens and 1,024 anchors per rank, world size 4 (65,536 tokens / 4,096 anchors per step) |
| Checkpoints | `--checkpoint-freq 0.0625` (Yu's final setting), resume from the save path |
| Trainer | speculators `7046ac6` with Yu's patch (pruned output head, process-group timeout `SPEC_PG_TIMEOUT_MIN=60`) |

## Changed because of the 70B

| Item | 8B | 70B |
|---|---|---|
| Corpus | 8B answers | 70B answers |
| Target layers | 1 8 15 22 29 | 1 20 39 58 77 (same rule: five evenly spaced from 1 to n−3) |
| Drafter width | hidden 4096, MLP 21,504 (~1.5B trainable) | hidden 8192, MLP 43,008 (~6B trainable); speculators mirrors the verifier |
| Parameters | replicated | `--fsdp-shard` (fp32 weights + grads + Muon state ~75 GB unsharded) |
| Extraction server | one GPU | TP2 (72 GB of weights per GPU) |
| Hidden states | 46 KB/token | 98 KB/token; online extraction every epoch (`--on-generate delete`) as for the 8B |
| Job limit | 24 h (Daint) | 12 h (Clariden `normal`), so twice the chain links |

Layout per node, as Yu's v3: one TP2 extraction server on GPUs 0–1 and two trainer
ranks on GPUs 2–3, hidden states in node-local `/tmp`. Both ranks of a node share
their server. The run uses four such nodes (see Measured).

## Phases

1. **Prompts.** `make_opb_shards.py` on the downloaded revision; check the 1,358,781
   total and the per-source counts against Yu's manifest.
2. **Regeneration.** One node per part (each shard cut into parts), `--resume`, any
   number of nodes. A throughput pilot picks TP2×DP2 or TP4 per node.
3. **Merge.** Rows written in the order of the 8B corpus; every 8B id must be
   present (failed rows retried). Same id order and count make prepare-data's seed-0
   permutation select the same held-out rows; checked against `val_ids.txt`.
4. **Prepare.** As for the 8B.
5. **Training pilot** (debug, 2 nodes): TP2 extraction writes the right tensors
   (shape, and top-1 agreement of the last layer through norm and `lm_head` with the
   next token), the trainer fits with FSDP, step time and host RSS, kill and resume.
6. **Full run.** Chain of 12 h links; confirm after each change that steps advance.
   Export epochs 1, 2, 6 and 10 as Yu did; prune intermediate checkpoints.
7. **Evaluation.** Trainer held-out curve against the 8B (5.12 → 5.94 expected
   accepted length), then the 64-prompt probe, k sweep and greedy equality on 70B TP4.

## Measured (2026-10-18)

- Every 70B vLLM server needs `--compilation-config.pass_config.fuse_allreduce_rms false`
  (as all launchers in this repo); without it CUDA-graph capture crashes at TP2 and TP4.
- Regeneration: TP4, 256 sequences, ~4.7k output tokens/s per node; array 3681366,
  32 parts on 16 nodes. 1,751,728 rows (8B: 1,809,684); 1,357,138 of 1,358,781
  conversations. 1,641 failed (prompt + 4,096-token cap above the 8,192 context);
  ~3 % of multi-turn conversations end earlier than in the 8B corpus because the
  regeneration stops a conversation once a turn passes 4,096 tokens (70B answers:
  mean 816 tokens, 8B 515).
- Split (job 3691346): 1,576,555 training / 175,173 held out, of which 174,942 are
  rows of the 8B run's held-out set (the rest of that set was not regenerated);
  verified with Yu's val_ids.py. Corpus, val_ids.txt and missing-ids.txt in
  `infra01/speculative-decoding/dspark-opb-70b-thinking-off/`.
- Hidden states from the TP2 extraction server: shape (tokens, 6, 8192), last layer
  through norm and lm_head predicts the next answer token 98.3 % of the time.
- Training layout: 4 nodes, 8 ranks × 8,192 tokens × 512 anchors (Yu: 4 × 16,384 ×
  1,024, the same 65,536 tokens and 4,096 anchors per step). Four nodes is the most
  that keeps this batch while a rank still fits an 8,192-token conversation.
- 3.56 s per step, ~33,200 steps per epoch (~33 h), 10 epochs ~14 days of compute.
  Host RAM ~510–640 GB of 856; trainer GPUs 82–97 GB; checkpoint 25 GB, one
  directory per epoch.
- Chain: run id `opb-thinkoff`, jobs 3691347–3691384 (12 h each). Each saves a
  resumable checkpoint 40 min before its time limit (speculators-deadline-stop.patch).
  Link 1 trained to step 2,209 and hung in a collective (no cause logged); link 2
  resumed from the step-2,076 checkpoint.
